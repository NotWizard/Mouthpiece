## 执行流程约束（每一项都必须遵守）
1. **实现与复核分离**：实现方与复核方必须是不同主体；复核独立读 diff + 跑全套测试，判 PASS/FAIL 附证据，FAIL 退回，禁止自我批准。
2. **每项一个独立 commit**：含 代码 + 回归测试 + CHANGELOG [Unreleased] 条目；提交信息中英双语、结构化（AGENTS.md）。
3. **测试只增不减**：基线 117，每项 +≥1；不得削弱/删除现有测试；纯 UI 项注明手动验证步骤。
4. **根因修复**：禁止创可贴；已证伪/降级项按末表处理。
5. **构建纪律（本轮教训）**：验证用 **clean 构建**（`xcodebuild ... clean test`）避免增量缓存假绿；**同一时刻只跑一个 xcodebuild**，避免共享 build service 死锁；每步提交后用独立命令硬核验 `git status --porcelain` / `git rev-parse` / 关键符号 grep，不轻信任何“已完成”口头报告。
6. **顺序**：P0（已完成）→ P1 → P2 → P3；同级按 ID。可并行开发**文件域互不冲突**的项，但复核与提交串行。
7. 遇阻塞：标 BLOCKED + 原因，跳过继续，最后统一汇报。单项连续 3 次复核 FAIL 或需删测试才能过 → 停下汇报，不硬推。

## R3. 方案修正（依据官方文档）
- **P1-3（Secure Input）**：`IsSecureEventInputEnabled()` 是唯一公开 API 且方向正确，但它是**全局状态、非按字段**（TN2150：任一进程启用安全输入后，系统即停止向拦截进程投递键盘事件）。故它"为真"可可靠预测粘贴会被丢弃，但"为假"不等于安全 → **需配合插入后校验**（读回/无变化检测），不可只依赖该标志。
- **P1-5（热键）**：方案正确。按物理 keyCode 跟踪（右 Cmd=54、左 Cmd=55、Shift 56/60、Option 58/61、Control 59/62）；tap 因超时被禁后用 `CGEventSource.keyState(.combinedSessionState, key:)` 重算按压态。设备相关掩码（`NX_DEVICELCMDKEYMASK`）为半私有替代，优先用 keyCode。
- **P1-9 / P1-14（签名校验）**：`SecStaticCodeCreateWithPath` + `SecRequirementCreateWithString` + `SecStaticCodeCheckValidity` 是对的 API，**但本 App 自签名、无 Apple 锚定 Team ID**，`anchor apple generic and leaf[subject.OU]=TEAMID` 不可用；只能锚定自身 leaf 证书 / `cdhash` / `identifier`（弱 pin）。且 `com.apple.security.cs.disable-library-validation` 允许运行时加载任意签名者的库，进一步削弱强需求。**真正有效的控制是路径限制（只从 `Bundle.main` 解析）**；签名校验作为附加项，需求串按自身身份而非 Team ID 书写。
- **P1-13（Soniox）**：marker 集合 `{"<end>","<fin>"}` **已由官方文档 + Soniox 自家 SDK `filterSpecialTokens()` 确认**（原始 WebSocket 客户端必须自行过滤），**取消**原"需线上确认"的 UNCERTAIN 标注。
- **P2-12（模型校验）**：CryptoKit `SHA256` 增量哈希 + 分块读取 + `replaceItemAt` 原子替换是正确模式（Apple 无专门下载校验 API）。注意经 `huggingface_hub` 的模型上游已做完整性校验，再 pin 属冗余（无害）。
